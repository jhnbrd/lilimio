A clearer view of the heat, with a redesigned interface and more flexible location selection.

### What’s new

- A forest-and-ivory interface with bottom-anchored navigation and footers, readable controls and focused detail dialogs.
- Planning and relief lists show as many options as fit, adapting when the window resizes. Today’s weather display scales on taller screens, and the daily forecast no longer leaves a large gap above its rows.
- Search for a street, barangay, district or city, use optional GPS, or select a map pin. Relief searches can reuse your forecast location.
- Recent location searches are cached in memory for five minutes, and cancelled searches no longer leave stale timeout messages.
- Optional photos linked to the exact OpenStreetMap place, with Wikimedia attribution and license information when available.
- Smoother interactions, reduced-motion support, revised onboarding, and clearer source and privacy explanations.

### Accuracy and availability

Precise coordinates do not imply street-level temperature accuracy. Forecasts estimate conditions across an area; shade, buildings and surfaces can change how hot it feels. PAGASA station observations remain separately labeled and are not substituted into the forecast. Plans are experimental, and mapped facilities are unverified.

Location searches and photos depend on external providers and can be slow or unavailable. No stock or guessed place photo is substituted when an exact link is missing.

### Updating an existing installation

Rebuild both Docker Compose services after pulling this version. Existing saved plans, places and preferences remain in browser storage. Installed PWA clients may need to select **Update now** or reload after the server update.

### Validation

58 automated tests, TypeScript checking, production build and the offline-download budget pass. Browser checks cover 90 route/viewport combinations, additional dialog states, list resizing and location-selection flows using fixtures. Live photo coverage and physical-device performance remain outside those checks; Docker smoke checks run in GitHub Actions.

Publishing this release does not deploy the app. Production deployment is recorded separately after the owner verifies the manual server update.
